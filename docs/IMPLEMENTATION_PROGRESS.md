2026년 10월 27일 통합 검사: Python 94개, Node.js 72개 전부 통과했다. Python 검사는 엔진·HTTP·실제 ASGI WebSocket·방 규칙·저장·학습 계약을 포함한다. 네트워크 응답이 사라져도 이미 적용한 플레이어 입력을 다시 적용하지 않으며, 로그라이크는 worker 장애 후 저장 checkpoint에서 복구한다. 싱글·런·멀티플레이가 애플리케이션 소유의 한 worker를 공유한다.

Ego 브라우저에서 추천 팀으로 싱글 전투, 로그라이크 생성·행동·새로고침 후 복원, 두 탭 방 생성·참가·전투를 확인했다. 멀티플레이는 p1/p2 시점의 비공개 상대 벤치를 숨겼으며, p2가 2턴에 새로고침한 뒤 같은 역할·턴·HP `[82, 183, 202]`로 복원되었다. 로그라이크도 2턴의 HP `[84, 184, 202]`를 그대로 복원했다. 재접속 자동화 검사는 60초 유예, 중복 연결 거부, 대기 중 입력 유지와 제한시간 재개를 포함한다.

현재 신경망은 아래 후속 4에서 검증한 실험 모델이며 기본 컨테이너는 규칙 AI를 제공한다. 브라우저 기록·도감은 해당 브라우저에 저장되며 런 SQLite와 분리되어 있다. 영구 능력치 상승이나 계정 동기화는 구현 범위에 포함하지 않았다. Docker 실행 검사는 로컬 Docker가 없어 GitHub Actions에서 수행했다. 커밋 `d060cec`에서 이미지 빌드·실제 엔진 전투·볼륨 재연결·읽기 전용 이미지의 HTTP 기동·정상 종료가 통과했다. 같은 실행의 Python 검사는 최신 FastAPI에서 제거된 검사 코드의 startup 메서드 때문에 실패하여 lifespan 컨텍스트로 수정했다. 최종 변경을 포함한 원격 검사 결과는 아래에 기록한다.

## 후속 4: AI 개선·분리 평가·재학습

공개 정보 휴리스틱의 무효 공격 반복, 강제 교체 슬롯·상성 판단, HP를 고려한 회복·상태 판단을 수정하고 이전 정책은 비교용으로 남겼다. 정예·보스의 누락된 EV는 기술의 물리·특수·방어 역할에 맞게 채우고 명시한 EV와 저장 checkpoint는 보존한다. 새 탐험에서 기본/전략을 선택할 수 있으며 전략 탐험의 새 정예·보스 전투에 개선한 정책을 적용한다. 과거 저장 전투는 정책 식별자가 없으면 기존 위력 우선으로 이어진다. 알 수 없는 미래 난이도·정책은 백업 보관은 허용하되 현재 버전 복원은 거부한다.

30종의 팀 조합·EV/도구 빌드·seed를 train/validation/test로 분리했다. 조합 수는 2,842/637/581개이고 같은 종과 기술은 공유한다. 모방 학습 8,192표본과 실제 엔진 PPO 65,536단계를 완료했으며 검증으로 선택한 후보는 모방 학습 이후 PPO 16,384단계다. PPO 자기 대전 1,716경기에서 p2 모델 호출 23,816회와 스냅샷 갱신 128회를 기록했다. 최종 test 결과로 가중치·정책·후보를 다시 조정하지 않았다.

고정 평가 4,500경기에 이어 독립 seed에서 팀과 좌석을 교환하는 추가 확인 1,500경기를 실행했다. 실험 후보의 이전 bootstrap 상대 승률은 최초 72.0%, 추가 확인 70.2%(pair-bootstrap 95% 구간 66.6–73.8%)였다. 후보의 규칙 AI 상대 승률은 19.8%라 규칙 AI를 계속 권장한다. 규칙 v2 대 기존 규칙의 추가 확인은 51.4%(48.6–54.2%)여서 일반적 성능 우위를 입증하지 못했다. 6,000경기 전체 불법 행동·제한 초과는 0이고 최초 후보 평가의 상대별 추론 p95 최댓값은 1.80ms였다. 이 평가는 새 체력의 3대3이며 로그라이크 완주율이나 미학습 종 일반화를 의미하지 않는다.

검증 조건을 통과한 `training/models/expedition-v2.pt`를 PyTorch 환경의 실험 신경망 기본 파일로 적용했다. SHA-256은 `20c634f38af9483217c005961b3d00ce53b9af780c825edb5600a5679f6e5610`이며 이전 bootstrap을 보존했다. 기본 Docker에는 PyTorch·신경망 모델을 포함하지 않으며 규칙 AI로 동작한다. [학습 안내](../pokemon_rl/training/README.md)와 [평가 규약](AI_EVALUATION_PROTOCOL.md)에 예산·선택 과정·모델 hash·원시 결과·재현 명령·한계를 기록했다.

브라우저에서 전략 탐험 생성과 실험 신경망의 실제 전투 2턴·HP `[138, 183, 202]`를 확인했다. 기존 합법 파티·행동 정책을 바꾸지 않은 기본 탐험 20구간 완주 검사도 통과했다. 로컬 전체 Python 157개 중 156개 통과·Windows 심볼릭 링크 권한 검사 1개 건너뜀, Node.js 92개 전부 통과했다.

4번 구현·모델·보고서를 `cdfb8ff`로 커밋·푸시했다. [최종 GitHub Actions](https://github.com/dndjd321/FreeFolder/actions/runs/40509699679)의 Linux 환경에서는 Python 157개·Node.js 92개가 모두 건너뛰기 없이 통과했고 의존성 호환 검사도 통과했다. Docker 이미지 빌드·실제 전투·영속 볼륨·읽기 전용 HTTP 기동·온라인 백업→새 경로 복원→동일 런 재개·정상 종료가 성공했다. Render가 엔진 0.11.11, 20구간과 기본/전략 모드 응답, 보스 예고·탐험 모드·실험 모델 표시 스크립트를 제공하는 것을 읽기 전용 HTTP로 확인했다. 운영 서버의 신경망 사용 가능 값은 `false`이며 기본 규칙 AI를 제공한다.

## 후속 5: 여러 탭·지연 입력의 탐험 버전 검사

이전 전투의 revision 0 입력이 다음 전투의 revision 0에 적용되는 경로를 재현하고, 모든 HTTP 탐험 변경에 최상위 `run_revision`을 검사하도록 수정했다. 인증·런 버전 검사·변경을 같은 잠금 안에서 수행하고, 버전과 상태는 같은 SQLite commit에 기록한다. 충돌한 입력은 409 `RUN_STALE`로 거부한다. 브라우저는 현재 상태만 복구한 뒤 내용을 확인하고 다시 선택하도록 안내하며 옛 행동을 다시 전송하지 않는다.

과거 저장은 런 버전 0으로 읽는다. 이미 받은 전투 명령의 같은 ID·행동은 기존 멱등 복구를 유지하며, 새 명령이나 다른 전투에서 넘어온 입력에는 최신 버전이 필요하다. 새 요청 회귀 12개를 포함한 런 검사 50개, Node 전체 96개가 통과했다. 저장 도구는 21개 중 20개 통과·Windows 심볼릭 링크 권한 검사 1개 건너뜀이다.

5번은 `b16e25c`로 커밋·푸시했다. [원격 Linux·Docker CI](https://github.com/dndjd321/FreeFolder/actions/runs/40520060891) 성공과 실제 두 탭의 409 거부→200 재개→동일 1턴·재선택 안내를 확인했다.

## 후속 6: 다중 탭의 최근 탐험 접근정보 보존

하나의 10개 배열 대신 런별 독립 기록을 이어하기 정보의 기준으로 사용한다. 구형 목록·단일 접근정보를 이전하며, 목록 캐시가 다른 탭에서 덮여도 독립 기록을 읽어 복구한다. 진행 중 9개에서 두 탭이 동시에 생성해 11개가 되어도 모두 보존·표시하고 새 생성만 제한한다. 명시적 제거는 독립 표식으로 남겨 늦은 응답·옛 목록이 접근정보를 되살리지 못하게 한다.

용량이 부족하면 이전을 마친 목록 캐시만 비워 기록 저장을 재시도한다. 이전 도중 저장이 실패하면 원본 목록을 보존하고 현재 탭의 접근정보와 저장 불가 안내를 유지한다. 두 VM의 공유 Storage 경쟁, 응답 역순, 구형 목록 덮기, 이전·삭제·용량 부족·준비 화면 갱신 등 신규 7개 포함 Node 전체 103개가 통과했다. 표시 요약의 모든 순간적 갱신 경쟁을 해결한 것은 아니며 실제 진행은 인증된 서버 재개가 기준이다.

6번 `268f919`와 다른 탭 갱신 중 직접 선택한 파티·난이도 보존 보완 `20bc69d`를 각각 커밋·푸시했다. 보완 회귀 포함 Node 104개가 통과했다. 실제 브라우저 두 탭에서도 정상 생성 9개 이후 두 동시 생성 응답을 역순 처리해 11개 모두 보존·표시, 이전 9개 유지, 새 생성 비활성을 확인했다.

## 후속 7: 전투 준비와 회복 선택

전투·정예·보스 준비에서만 팀과 자원을 함께 재배열하는 `party/order`를 추가했다. 순열·살아 있는 선두·인증·최신 런 버전을 검사하고, 전투 중과 보상·휴식·상점 등 다른 단계에서는 거부한다. 공개 파티의 기술에 한국어 이름·타입·분류·위력·최대 PP를 제공하며 DB의 자원이나 빌드를 덮어쓰지 않는다.

쉼터·상점은 미리보기와 실제 적용이 같은 회복 함수를 사용한다. 특전·상한·기절·자동 치료·부활을 반영해 자원 복사본의 전후값을 계산한다. 별도 helper 13개와 서비스 11개를 포함한 런 검사 74개가 통과했고 기존 실제 20구간 완주도 통과했다. 전체 Python 194개 중 193개 통과·Windows 권한 검사 1개 건너뜀이다. 화면 연결과 브라우저 검증을 이어서 진행한다.

서버 묶음은 `c0b2a99`로 커밋·푸시했다. 이어서 준비 화면의 선두 선택, 기술별 이름·현재/최대 PP·타입·분류·위력, 실제 회복 전후값과 동료별 상세를 연결했다. 기절한 선두·전투 중 변경·오래된 렌더 핸들러를 차단하고, 소모된 도구를 다시 표시하지 않는다. 무효과 쉼터 선택의 진행 가능성과 부활 불가 상태를 구분한다. 폼 타입은 기본종 번호로 추정하지 않는다. 프론트 신규 9개 포함 Node 전체 113개가 통과했다.

실제 브라우저에서 한카리아스 선두 변경 전후 자원이 모두 같았고 실제 1턴 출전도 일치했다. 이후 공개 API로 합법 전투·보상·분기 입력 19회를 진행해 첫 쉼터에 도착했다. HP `[0, 151, 125]`에서 부활 미리보기의 총 HP 276→368·선두 HP 0→92가 실제 UI 선택 후 각 동료의 HP·PP·상태와 일치했다. 획득한 에테르 케이스의 PP 12 회복 문구, 무효과 상태 치료의 진행 안내도 확인했다. 360/390px의 DOM 문서 폭과 화면 폭이 같고 주요 버튼 높이는 47.5px였다. 창 최소화로 이미지를 캡처하지 못해 DOM·동작 계측 결과로 기록한다.

최종 공개 메타는 지원 30종 전체를 실제 엔진의 타입·도감 번호와 대조했다. 워시로토무는 기본 로토무의 전기/고스트로 추정하지 않고 전기/물을 제공하며, 따라큐는 로컬 `mimikyu-disguised`와 엔진 `Mimikyu`의 명시적 이름 별칭을 처리한다. 메타는 공개 복사본에만 붙이고 저장·전투 규칙·추가 RPC를 변경하지 않는다. 최종 로컬 Python 195개 중 194개 통과·Windows 권한 검사 1개 건너뜀, Node 113개 전부 통과했다. 서버 묶음의 [Linux·Docker CI](https://github.com/dndjd321/FreeFolder/actions/runs/40523013501)도 성공했다.

화면과 최종 메타를 `118b856`으로 커밋·푸시했다. [최종 GitHub Actions](https://github.com/dndjd321/FreeFolder/actions/runs/40524621851)는 Python 195개·Node 113개를 건너뛰기 없이 모두 통과했고 의존성 호환 검사도 성공했다. Docker 빌드·실제 전투·온라인 백업→새 경로 복원→동일 런 재개·읽기 전용 HTTP 기동·정상 종료가 통과했다. Render의 20구간·따라큐 ID 778 응답과 최신 런 버전 검사·독립 접근정보 저장·선두 변경·회복 미리보기 스크립트 제공을 확인했다. 후속 5–7번은 완료했으며 다음 우선순위는 [개발 계획](NEXT_DEVELOPMENT_PLAN.md)의 8–10번이다.
