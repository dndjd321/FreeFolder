1·2번에 이어 3·4번을 구현·검증했다. 4번은 30종을 공유하되 팀 조합·빌드·seed를 학습/검증/최종 평가로 분리했다. 기존 6종 평가와 모집단이 달라 승률의 직접 증감으로 비교하지 않는다. 새 신경망은 이전 bootstrap과 직접 대전한 추가 확인에서 70.2%였으나 규칙 AI 상대는 19.8%여서 실험 선택지로 제공하고 규칙 AI를 계속 권장한다.

AI·콘텐츠 검토에서 확인한 무효 공격 반복·원래 슬롯을 고려하지 않는 교체 판단과 정예·보스의 특수공격 EV 덮어쓰기를 수정했다. 기본 탐험은 기존 위력 우선 흐름을 유지하고 전략 탐험의 새 정예·보스 전투에는 개선한 공개 정보 정책을 적용한다. 저장된 과거 전투는 기존 정책·능력치·자원으로 복원한다.

백업·복원은 서버 운영용 기능이다. 브라우저에서 임의 HP·재화·승패·checkpoint를 업로드하는 기능은 추가하지 않는다. 온라인 백업은 서버가 마지막으로 commit한 경계를 보관하며, 복원 후에는 해당 경계의 전투 입력을 고정 엔진으로 재생한다. 백업 파일에는 개인 런 접근에 필요한 서버 기록이 있으므로 공개 저장소에 올리지 않는다.

복원은 기존 DB를 덮어쓰지 않고 새 경로에 생성한다. 운영자가 백업 검사를 확인한 뒤 서버를 정지하고 저장 디렉터리를 전환한다. 영속 디스크 설정만으로 외부 백업까지 보장되지는 않으며, 동일한 임시 디스크에 둔 백업도 재배포 시 함께 사라질 수 있다.

최근 탐험 목록은 해당 브라우저의 접근정보를 보존한다. 서버의 SQLite, 다른 브라우저 프로필, 계정 동기화를 대신하지 않는다. 목록에서 제거해도 서버의 탐험을 삭제하지 않는다.

5번 커밋·푸시 `b16e25c`의 [Linux CI와 Docker 검사](https://github.com/dndjd321/FreeFolder/actions/runs/40520060891)가 통과했다. 실제 두 브라우저 탭에서 첫 탭이 시작한 전투를 옛 탭이 다시 시작하려 하자 409로 거부하고 `/resume` 200으로 동일한 1턴 상태와 재선택 안내를 보여주는 것을 확인했다.

6번 검증: 두 VM이 같은 Storage를 공유하는 동시 생성·응답 역순·옛 목록 덮어쓰기에서 진행 중 11개 접근정보를 모두 보존했다. 삭제한 기록은 늦은 응답이 도착해도 목록으로 복구되지 않는다. 신규 회귀 7개 포함 Node 전체 103개 통과. 동일 런의 순간적인 요약 갱신 경쟁까지 최신 표시를 보증하는 것은 아니며 실제 진행은 서버 재개 응답이 기준이다.

6번은 `268f919`, 다른 탭 갱신 중 편성 선택 유지 보완은 `20bc69d`로 각각 커밋·푸시했다. 보완 회귀 포함 Node 전체 104개가 통과했다. 실제 두 브라우저에서도 정상 생성한 9개에 두 동시 생성 응답을 역순으로 전달해 11개가 모두 남고, 이전 9개 보존·중복 ID 없음·새 생성 비활성을 확인했다.

7번 서버 구현 검증: 파티 순서 변경, 공개 기술 메타, 실제 적용 함수를 공유하는 회복 미리보기를 완료했다. 실제 엔진의 선두 교체·서버 재시작 후 HP·PP·수면·소모 도구·명시 EV 보존을 확인했다. 서버 묶음 `c0b2a99`의 [Linux CI와 Docker 검사](https://github.com/dndjd321/FreeFolder/actions/runs/40523013501)가 통과했으며 이후 아래 화면 검증과 타입 메타 대조를 완료했다.

7번 화면도 연결했다. 준비 단계의 살아 있는 동료만 선두로 바꿀 수 있으며, 서버 응답을 받은 뒤 순서를 표시한다. 기술별 이름·PP, 서버가 계산한 회복 전후값과 부활·치료 인원, 동료별 상세를 보여준다. 무효과 쉼터도 선택해 진행할 수 있고 부활할 동료가 없으면 해당 선택을 비활성화한다. 폼은 기본종의 타입으로 추정하지 않고 서버의 정확한 타입을 우선한다. Node 전체 113개가 통과했다.

실제 브라우저에서 모든 자원을 보존해 한카리아스를 선두로 바꾼 뒤 해당 포켓몬으로 출전했다. 공개 API의 합법 입력으로 두 전투를 진행한 후 쉼터에 도달했다. 부활 미리보기의 파티 HP 276→368, 기절 동료 HP 0→92와 실제 UI 선택 결과가 동료별 HP·PP·상태까지 일치했다. 특전이 적용된 PP 12 회복 문구도 확인했다. 360px 준비·쉼터와 390px 분기의 DOM 문서 폭은 화면 폭과 같고 주요 버튼 높이는 47.5px였다. 창 최소화로 이미지 캡처는 수행하지 못했으며 이 검증은 DOM·동작 계측이다.

최종 메타 검증에서 지원 풀 30종의 공개 타입·도감 번호를 실제 엔진과 대조했다. 워시로토무의 전기/물 타입과 따라큐의 이름 별칭을 처리했고, 공개 정보 목록 수정이 서버 캐시·DB를 바꾸지 않도록 복사한다. 로컬 전체 Python 195개 중 194개 통과·Windows 권한 검사 1개 건너뜀, Node 전체 113개 통과. 전투 정책·모델·콘텐츠·저장 버전은 바꾸지 않았다.

7번 화면·최종 메타는 `118b856`으로 커밋·푸시했다. [최종 Linux CI](https://github.com/dndjd321/FreeFolder/actions/runs/40524621851)에서 Python 195개·Node 113개가 건너뛰기 없이 전부 통과하고 의존성 호환 검사도 성공했다. Docker 빌드·실제 전투·온라인 백업·복원·동일 런 재개·읽기 전용 HTTP 기동·정상 종료가 통과했다. Render의 20구간·따라큐 ID 778 응답과 런 버전·독립 접근정보·선두 변경·회복 미리보기 스크립트 제공을 읽기 전용 HTTP로 확인했다.

## 1·2번 검증 기록

- 1번 구현·로컬 검증 완료: 실행 중 DB 온라인 백업, 새 경로 복원, 임대 잠금, 쓰기 실패 후 checkpoint 복구. 실제 브라우저에서 복원한 DB의 2턴 탐험을 같은 ID·HP로 재개했다.

- 로컬 통합 검사: Python 118개 중 117개 통과, Windows 심볼릭 링크 권한이 필요한 1개 건너뜀. 이후 추가한 스키마 필수 값 검사도 별도로 통과했다. Node.js 82개 전부 통과.
- 원격 최종 검사: `0dd55c0`의 [GitHub Actions](https://github.com/dndjd321/FreeFolder/actions/runs/40501020618)에서 Python 119개와 Node.js 82개가 건너뛰기 없이 통과했다. 컨테이너에서 실행 중 DB 백업→새 경로 복원→동일 런 전투 재개도 통과했다.
- 커밋·푸시: 저장 보호 `6176bd9`, 최근 탐험 목록 `79b489f`, 독립 검사 수명 정리 `0dd55c0`. 운영 서버의 새 저장 상태 응답과 최근 탐험 스크립트 제공을 확인했다. 영속 디스크 또는 외부 백업 저장소를 새로 설치한 것은 아니다.

## 3번 플레이 흐름 검증

- 서버가 콘텐츠 일정에서 20구간의 완료·현재·예정 상태와 5·10·20구간 보스의 대비 정보를 계산한다. 분기는 위험도 분류·테마·대비할 점·현재 특전 기준 보상을 비교하며 같은 위험도와 기본 보상이라는 사실을 명시한다. 기존 저장 형식이나 비공개 상대 빌드는 바꾸지 않는다.
- 추천 파티 시작과 실제 전투, 2턴에서 준비 화면 이동 후 같은 HP·턴 복귀를 확인했다. 별도 합법 파티로 서버 API와 UI를 함께 사용해 보상·영입·분기·쉼터·보스·상점·20구간 완주 결과를 확인했다. HP·재화·승패·DB 진행 단계를 조작하지 않았다. 패배 결과도 확인했다.
- 360px 보스 화면과 390px 분기 화면에서 문서 가로 폭이 화면 폭과 같고, 주요 버튼 높이가 약 47px 이상이었다. 모바일 전투는 파티 카드를 한 열로 배치하고 오류와 저장 상태 재시도를 보이는 도구 영역에 표시한다.
- 신규 여정 검사 8개와 기존 런 검사 20개, Node 전체 88개가 통과했다. `942af9a`를 커밋·푸시하고 [Linux CI와 Docker 검사](https://github.com/dndjd321/FreeFolder/actions/runs/40505482427)가 성공한 뒤 4번 본 훈련을 진행했다.

## 4번 AI 개선·평가·재학습

- 모방 학습 8,192표본과 PPO 65,536단계를 실제 엔진에서 실행했다. 검증 점수로 선택한 모델은 모방 학습 이후 PPO 16,384단계의 체크포인트다. 자기 대전은 p2 모델 호출 23,816회·1,716경기·128회 스냅샷 갱신을 기록했다.
- 최초 고정 평가 4,500경기와 독립 seed의 좌석·팀 교환 확인 1,500경기를 수행했다. 후보 대 이전 bootstrap 확인 승률은 70.2%, pair-bootstrap 95% 구간은 66.6–73.8%다. 6,000경기의 불법 행동·제한 초과는 모두 0이다.
- 규칙 v2 대 기존 규칙 확인 승률은 51.4%, 구간 48.6–54.2%이므로 전반적인 성능 우위를 주장하지 않는다. 알려진 판단 오류의 수정과 실험 신경망의 개선을 구분한다. 모델·정책은 최종 test 후 다시 조정하지 않았다.
- 기본/전략 탐험 생성·기록·재개를 지원한다. 브라우저에서 전략 탐험 생성과 새 실험 신경망의 실제 2턴 진행을 확인했다. 기존 합법 파티·정책을 바꾸지 않은 기본 탐험 20구간 완주 검사도 통과했다.
- 로컬 전체 검사: Python 157개 중 156개 통과, Windows 심볼릭 링크 권한이 필요한 1개 건너뜀. Node.js 92개 전부 통과.
- 재현 명령·원시 평가·모델 hash·승격 조건·한계는 [학습 안내](../pokemon_rl/training/README.md)와 [평가 규약](AI_EVALUATION_PROTOCOL.md)에 보관한다. 기본 Docker 서버는 규칙 AI를 제공하고 신경망은 PyTorch를 설치한 환경에서 사용할 수 있다.
- 커밋·푸시 `cdfb8ff`의 [최종 Linux CI](https://github.com/dndjd321/FreeFolder/actions/runs/40509699679)에서 Python 157개·Node.js 92개가 건너뛰기 없이 통과했다. Docker 이미지·실제 전투·온라인 백업·복원·동일 런 재개·정상 종료도 통과했다. Render의 20구간·기본/전략 모드 응답과 보스 안내·모드 선택·실험 모델 표시 스크립트 제공을 확인했다. 운영 서버는 신경망 사용 불가를 명시하고 규칙 AI를 제공한다.
