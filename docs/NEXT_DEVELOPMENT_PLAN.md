1번과 2번을 마친 뒤 3번을 구현·검증했다. 이어서 4번의 기준 AI 수정, 30종 학습·검증·최종 평가 분리와 재학습을 진행한다. AI의 기존 6종 개발 풀 평가는 분리 seed만 사용했고 같은 종·빌드를 공유한다. 초기 모델의 휴리스틱 상대 승률은 5.6%였으므로, 학습 시간을 늘리기 전에 팀 분리 평가와 기준 정책부터 확대한다.

AI·콘텐츠 후속 검토에서 `training/policies.py`의 자발 교체 점수는 항상 -5여서 위력 0인 무효 공격보다도 낮고, `run_service.py`의 정예·보스 EV는 모두 특수공격 중심으로 덮어써지는 것을 확인했다. 4번 작업은 이 기준 정책과 파티 설계부터 회귀 사례를 만들고, 30종 평가 기준선을 측정한 뒤 학습 예산을 정한다.

백업·복원은 서버 운영용 기능이다. 브라우저에서 임의 HP·재화·승패·checkpoint를 업로드하는 기능은 추가하지 않는다. 온라인 백업은 서버가 마지막으로 commit한 경계를 보관하며, 복원 후에는 해당 경계의 전투 입력을 고정 엔진으로 재생한다. 백업 파일에는 개인 런 접근에 필요한 서버 기록이 있으므로 공개 저장소에 올리지 않는다.

복원은 기존 DB를 덮어쓰지 않고 새 경로에 생성한다. 운영자가 백업 검사를 확인한 뒤 서버를 정지하고 저장 디렉터리를 전환한다. 영속 디스크 설정만으로 외부 백업까지 보장되지는 않으며, 동일한 임시 디스크에 둔 백업도 재배포 시 함께 사라질 수 있다.

최근 탐험 목록은 해당 브라우저의 접근정보를 보존한다. 서버의 SQLite, 다른 브라우저 프로필, 계정 동기화를 대신하지 않는다. 목록에서 제거해도 서버의 탐험을 삭제하지 않는다.

## 3번 플레이 흐름 검증

- 서버가 콘텐츠 일정에서 20구간의 완료·현재·예정 상태와 5·10·20구간 보스의 대비 정보를 계산한다. 분기는 위험도 분류·테마·대비할 점·현재 특전 기준 보상을 비교하며 같은 위험도와 기본 보상이라는 사실을 명시한다. 기존 저장 형식이나 비공개 상대 빌드는 바꾸지 않는다.
- 추천 파티 시작과 실제 전투, 2턴에서 준비 화면 이동 후 같은 HP·턴 복귀를 확인했다. 별도 합법 파티로 서버 API와 UI를 함께 사용해 보상·영입·분기·쉼터·보스·상점·20구간 완주 결과를 확인했다. HP·재화·승패·DB 진행 단계를 조작하지 않았다. 패배 결과도 확인했다.
- 360px 보스 화면과 390px 분기 화면에서 문서 가로 폭이 화면 폭과 같고, 주요 버튼 높이가 약 47px 이상이었다. 모바일 전투는 파티 카드를 한 열로 배치하고 오류와 저장 상태 재시도를 보이는 도구 영역에 표시한다.
- 신규 여정 검사 8개와 기존 런 검사 20개, Node 전체 88개가 통과했다. 4번 본 훈련은 3번 커밋·푸시 뒤 시작한다.
