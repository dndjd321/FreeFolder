# 실제 탐험 밸런스 측정

2026년 10월 28일. 10a 측정 전에 아래 조건을 고정한다. 이 결과는 특정 자동 정책의 20구간 탐험 성과다. 실제 사용자의 완주율이나 새 체력으로 시작하는 3대3 AI 평가 승률로 해석하지 않는다.

- 파티: 현재 콘텐츠의 추천 리자몽·한카리아스·픽시 빌드를 그대로 사용한다.
- 시드: `run-balance-v1-000`부터 `run-balance-v1-019`까지 20개, 각각 `normal`·`hard` 순서로 실행한다.
- 전투: 공개 p1 관측만 사용하는 고정 `BaselinePolicy('heuristic', seed=0)`.
- 경제·진행: `public-economy-v1`. 생존 파티 HP 65% 미만·PP 35% 미만을 회복 필요로 판단하고 기절·상태·제공된 선택·가격만 사용한다. 첫 분기·첫 영입 후보를 고르며 임의 재추첨·선두 변경은 하지 않는다. 정확한 우선순위는 보고서의 `metadata.policy`에 보관한다.
- 제한: 한 런 1,000회 서비스 입력, 전투 관측 턴 200 초과 시 다음 입력 전에 중단한다. 중단·엔진 오류·미실행은 정상 패배와 구분하고 배치 종료 코드를 실패로 반환한다.
- 원본성: 공개 API와 동일한 `perform`의 런 버전·제시된 ID·합법 전투 입력만 사용한다. HP·승패·DB 진행·상대 비공개 빌드를 수정하거나 읽어 판단하지 않는다.
- 기록: 새 탐험의 버전 1 전체 journal을 요구한다. 모든 응답에서 순번별 이벤트를 모아 서버 상세 상한 128개 이후에도 측정 자료를 보존한다. 누락·변경은 오류다.
- 자원: 구간 입장·전투 종료·경제 선택의 경계에서 HP/PP 순변화·기절·실제 회복·수입/지출을 측정한다. 전투 중 누적 피해나 기술 회복 총량과 다르다.
- 재현성: 시드·팀·정책·콘텐츠·엔진·관련 코드 hash와 Git 상태를 보고서에 남긴다. 보고서는 기존 파일을 덮어쓰지 않는다.

저장소 루트에서 실행한다. 먼저 구현과 조건을 커밋해 작업 트리를 깨끗하게 한 뒤 본 측정을 실행한다.

```powershell
$env:OMP_NUM_THREADS='1'
Push-Location pokemon_rl
python -X utf8 -B -m balance.cli --report ../docs/research/run-balance-baseline-20261028.json
Pop-Location
```

짧은 실행 확인은 다른 보고서 경로와 `--seeds smoke-only-seed`를 사용한다. 보고서 생성 실패도 별도 실패 코드로 남는다. 서비스는 케이스마다 새로운 메모리 DB를 쓰며 엔진 하나를 공유하고 각 런 전투와 엔진을 종료한다. 운영 DB는 사용하지 않는다.

10b에서는 측정으로 확인한 병목만 작은 변경으로 조정한다. 같은 시드·파티·자동 정책·제한으로 전후 비교하며, 기존 저장은 과거 규칙을 유지할 수 있게 설계한다. 이 20개 시드에 맞춰 자동 정책을 튜닝하거나 공개된 최종 AI 평가로 다시 모델을 선택하지 않는다. 추가 콘텐츠·훈련은 별도 근거와 후속 평가가 필요하다.

10b 후보는 `normal-rescue-v2` 한 개로 고정한다. 기본 모드 3구간 쉼터의 `revive` 선택만, 입장 시 기절한 동료 전원을 각각 최대 HP 50%로 부활시키고 입장 시 생존한 동료를 최대 HP의 50%만큼 회복한다. 새로 부활한 동료에게 회복을 다시 적용하지 않는다. 다른 구간·선택·모드·PP·가격·상대·AI는 유지한다. 최초 구현 기본값은 과거 `balance-v1`로 두고 명시적 프로필로 비교한 뒤에만 신규 기본값 승격을 판단한다.

후보 결과를 읽기 전에 추가 확인 시드 `run-balance-holdout-v1-000`부터 `run-balance-holdout-v1-009`까지 10개를 고정한다. 과거/후보 각각 두 모드 20런씩, 총 40런을 추가 확인하며 이를 보고 후보 수치나 정책을 다시 바꾸지 않는다. 각 코호트에서 전략 모드 20/10런과 후보 영향을 받지 않은 기본 런은 이벤트·결과 동일성을 검사한다. 회복 공백 감소와 기본 모드 진행 결과를 함께 평가하고, 전체 난이도나 실제 사용자 완주율 개선을 주장하지 않는다.
